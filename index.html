自建 / 自己编辑的模型
实时负载

AMD Radeon Cloud（tokenfactory）各模型当前的并发占用，来自他们页面上 "Live capacity" 那份公开数据（后端去取，绕开跨域）。只有你把这块展开时才去取， 展开期间每 15 秒一次。

其它

导入 / 导出的是 profile（**不含密钥**：密钥用 Windows DPAPI 按当前用户加密， 换机器本来就带不走，导过去重新粘一次）。

新增供应商

选一个预设 → 使用默认模版 → 只补 API Key 就能用。都是 OpenAI 兼容写法（能填 base_url 的服务）。

DeepSeek 两种都支持：OpenAI 兼容填 https://api.deepseek.com， Anthropic 格式填 https://api.deepseek.com/anthropic。

不知道填多少就看服务商文档；填小了会频繁触发"压缩上下文"，填大了没坏处（超了服务端会报错）。

留 2048~8192 就行
高级

温度 = 回答的"随机性"：0 最稳（每次几乎一样，调试/工具调用建议 0~0.3）； 越高越发散（0.7~1.0 适合写东西）。这个助手要调工具、要准，建议 0.2。

这两个直接用上面**当前填的值**试，不用先保存

持久化数据（缓存）

这里是本软件在你这台机器上留下的**全部**数据：界面偏好、窗口状态、LLM 供应商与密钥、 对话历史、技能副本、MCP 配置、指令表、工作区文件…… 每一项都标了路径，可以单独删。 删除后软件会自动重启（避免半截状态）。

关于 KDock

KDock 以 Apache-2.0 开源，欢迎 issue / PR。第三方组件与借鉴声明见仓库里的 NOTICE。

版本管理

应用版本遵循语义化版本 MAJOR.MINOR.PATCH：不兼容改动升 MAJOR，加功能升 MINOR，修 bug 升 PATCH。 版本号在 src-tauri/tauri.conf.json、src-tauri/Cargo.toml、 package.json 三处保持一致，每次发版写进 CHANGELOG.md， 并打一个 vX.Y.Z 的 git tag。
固件包版本是另一套：.fw 包头里的三段式版本号（PD_HW.PD_SW.PD_FIX）， 由设备端规则决定是否允许升级/降级，和上面的应用版本无关。

知识库页面
