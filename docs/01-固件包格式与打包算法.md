# 功能说明：固件包（.fw）格式与打包算法

> 相关代码：`src-tauri/src/upgrade.rs`（`FW_MAGIC` / `parse_fw` / `make_fw` / `crc32` / `ver_u32`）

## 1. 这个功能解决什么问题

裸 `.bin` 只描**字节**，不描"这是什么版本、给哪块板、多大、有没有坏"。一旦有两个同名文件，
或者传输过程中掉了一个字节，靠肉眼和文件名根本分不出来。

所以升级包统一用 `.fw`：**64 字节包头 + 原始镜像**。包头里放版本号、payload 长度、
两处 CRC32、板卡名；上位机在**下载后、传输前、设备端校验时**三个环节都能拿它自检。

## 2. 包头布局（小端，共 64 字节）

| 偏移 | 长度 | 字段 | 说明 |
| ---: | ---: | --- | --- |
| 0 | 4 | `magic` | `0x5746594B`（ASCII `KYFW`）。认不出来就直接判"不是 .fw" |
| 4 | 2 | `hdr_ver` | 包头版本，当前 `1` |
| 6 | 2 | `hdr_size` | 包头长度，当前 `64` |
| 8 | 4 | `payload_size` | 镜像长度（不含包头） |
| 12 | 4 | `payload_crc32` | 镜像的 CRC32（多项式 `0xEDB88320`，初值 `0xFFFFFFFF`，末尾取反） |
| 16 | 4 | `hdr_crc32` | **包头自己的 CRC32**：算的时候把 `16..20` 这四个字节先当 0 |
| 20 | 4 | `fw_version` | 版本号，打包格式见下 |
| 24 | 4 | `target_addr` | 镜像要写到哪（裸 bin 用；hex/elf 自带地址时可忽略） |
| 28 | 4 | `timestamp` | 打包时间（Unix 秒） |
| 32 | 16 | `board` | 板卡名，C 字符串（高位补 0） |
| 48 | 16 | `note` | 备注，C 字符串 |
| 64 | N | payload | 原始镜像字节 |

## 3. 版本号编码

`fw_version` 是一个 u32：`0xA5 << 24 | major << 16 | minor << 8 | patch`，比如 `1.3.1` →
`0xA5 01 03 01`。

上位机显示时：

- `(v >> 24) == 0xA5` → 显示三段式 `major.minor.patch`；
- 否则按四段式显示并标注 `(旧格式)` —— 老包能读，但设备端的新规则一般会拒收。

`ver_u32("1.3.1")` 负责把人类写的版本号转成这个 u32，方便比较新旧。

## 4. 打包算法（`make_fw`）

```
1. 开一块 64 字节的全 0 缓冲区当包头
2. 依次写入 magic / hdr_ver / hdr_size / payload_size / payload_crc32
3. 写入版本号（ver_u32）、目标地址、时间戳、板卡名、备注
4. 先把 hdr_crc32 字段留 0，算整 64 字节的 CRC32，再写回 16..20
5. 包头 + 镜像 拼起来就是 .fw
```

上位机里这份实现是**格式对照用**（包通常由 MCU 工程侧的打包脚本生成），
但它和设备端打包器必须逐字节一致 —— 任何字段顺序/初值变化都会导致设备拒收。

## 5. 解析与校验（`parse_fw`）

按顺序做这几件事，任何一步不过就报明确的错：

1. 文件长度 ≥ 64；
2. `magic` 对得上（否则提示"裸 .bin 没有版本号，请先打成 .fw"）；
3. `hdr_ver` / `hdr_size` 是支持的组合；
4. **包头 CRC32** 对得上（把 16..20 清零再算）；
5. `payload_size + 64 == 文件长度`（防止截断/拼接）；
6. **payload CRC32** 对得上。

返回结构：版本号、payload 大小与 CRC、整文件大小与 CRC、板卡名。
上位机的"读版本"、升级前的自检、服务器包的核对，用的都是它。

## 6. 常见的坑

- **只改文件名不改内容**：版本号在包头里，改文件名不会改版本。
- **用文本编辑器打开再保存**：会把 `0x0D 0x0A` 之类改掉，CRC 立刻不过。
- **打包时忘了回填 `hdr_crc32`**：设备端报"包头 CRC 错"。
- **四段式老包**：上位机会提前拦下来并提示换三段式，别等到设备拒收。
- **板卡名不匹配**：设备端会报"板卡型号不匹配"（错误码 `-8`），说明拿错了包。
