# 功能说明：烧录（外部烧录器）

> 相关代码：`src/main.js`（`FL_TOOLS` / `bindFlash` / `flashBootstrap`）

## 1. 是什么

给"设备还是块白板、没有 bootloader、或者干脆跑飞了"的场景：用 **OpenOCD / J-Link /
STM32CubeProgrammer** 这类外部烧录器直接把镜像写进芯片 flash。

上位机不自己实现 SWD/JTAG 协议，只做三件事：

1. 按界面上的参数**拼命令行/脚本**；
2. 起进程，把 stdout/stderr **实时回显**到中间那块日志；
3. 把工具路径、型号、接口这些选择**记住**（存 localStorage），下次不用重填。

## 2. 支持的动作

| 动作 | 做什么 | 典型用途 |
| --- | --- | --- |
| 烧录 | 写入并校验，最后复位运行 | 产线/首件烧写 |
| 擦除 | 全片（或指定地址段）擦除 | 换固件前清干净 |
| 校验 | 只比对，不写 | 确认片上内容 |
| 复位 | 复位并运行 | 烧完手动看现象 |

## 3. 各烧录器怎么拼命令

### OpenOCD

```
openocd -f interface/<adapter>.cfg -c "adapter speed <kHz>" -f target/<target>.cfg \
        -c "program <file>[ <addr>] verify reset exit"
```

- `-f target/stm32f4x.cfg` 这类直接写目标配置名；
- `.bin` 必须给地址；`.hex`/`.elf` 自带地址，就不拼地址；
- 擦除走 `flash erase_address <addr> <len>`（默认 0x200000，可在界面改）。

### J-Link（脚本模式）

```
device <型号>
si <SWD|JTAG>
speed <kHz>
connect
loadfile <file>[ <addr>]      # .bin 需要地址
verifybin <file>, <addr>      # 只有 .bin 需要单独 verify
r
go
qc
```

代码把脚本写进临时文件再 `JLink.exe -CommanderScript`，比堆一长串 `-` 参数好排查。

### STM32CubeProgrammer CLI

```
STM32_Programmer_CLI -c port=SWD mode=UR -w <file> -v -rst
```

## 4. 界面参数

| 项目 | 说明 |
| --- | --- |
| 工具路径 | 三个 exe 的路径（默认给系统安装位置，可改，存 localStorage） |
| 适配器 / 接口 | `interface/stlink.cfg` 里的 `stlink`、`cmsis-dap`…或 J-Link 的 `SWD/JTAG` |
| 目标配置 / 芯片 | OpenOCD 的 `target/xxx.cfg`；J-Link 直接写芯片型号 |
| 速度 | kHz |
| 文件与地址 | `.bin` 需要地址，`.hex/.elf` 不用 |

## 5. 排错

| 现象 | 原因 |
| --- | --- |
| `Can't find <xxx>.cfg` | OpenOCD 的 `scripts` 路径没配（界面上有单独的 scripts 路径输入） |
| 连不上目标 | 探针没插稳、目标没供电、被 `option bytes` 锁了（STM32 需要先解锁） |
| 写完校验失败 | 速度太快 / 供电不稳；把速度降到 1000 kHz 以下试 |
| J-Link 找不到型号 | 型号名要写 J-Link 认的名字（老 `JLinkDevices.xml` 里可能没有新型号） |
| 烧完不跑 | 动作选了「复位」而不是「烧录」；或向量表地址/启动模式不对 |

## 6. 和"在线升级"的区别

| | 在线升级（串口 / 网口） | 烧录（外部烧录器） |
| --- | --- | --- |
| 需要拆机/接线 | 不用（用设备已有接口） | 要接调试口 |
| 需要 bootloader | 要 | 不要 |
| 换 Flash 布局 | 不行 | 可以（直接写任意地址） |
| 适合 | 现场维护、批量远程 | 首件、救砖、产线 |

两条路在同一个界面里，按手上的条件选一条即可。
