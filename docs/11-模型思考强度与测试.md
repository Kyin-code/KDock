# 模型思考强度与真实请求测试

## 数据模型

供应商 profile 同时保存两组值：

```text
reasoning_efforts = ["low", "medium", "high"]  # 这个模型声明支持的档位
reasoning_effort  = "medium"                   # profile 默认档；空=不发送
```

会话另有自己的 `reasoning_effort`。Agent 底栏选择后只影响当前会话，不修改供应商默认值。

## 协议映射

- OpenAI 兼容：请求体发送 `reasoning_effort`。
- Anthropic：映射为 extended-thinking `budget_tokens`；`none` 关闭 thinking。
- 空值：完全不发送该字段，交给服务端使用模型默认行为。

## 真实请求测试

设置 → 模型与供应商 → 高级：

1. 给模型勾选 2 个或更多确认支持的档位。
2. 点「测试真实思考强度」。
3. KDock 对每个档位各发一次相同的小请求。
4. 结果记录：接口返回的 reasoning 字符数、首字延迟、出字耗时、completion token、结束原因和错误。

这不是本地模拟。每次点击都会真实调用供应商 API，并产生少量 token 费用。

## 结果解释

- `reasoning_chars > 0`：接口暴露了思考正文，可比较不同档位的长度和延迟。
- `reasoning_chars = 0`：接口没有暴露隐藏 CoT；**不能据此断定模型没有思考**。
- 某档位返回 HTTP 400：该服务不支持这个档位，取消勾选即可。
- 同一档位的延迟/长度每次都会波动，单次样本只能作观察，不是能力基准。
